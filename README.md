# Бот заявок о поломках ТС

Водитель сообщает о поломке в Telegram, бот разбирает текст через OpenAI, уточняет недостающее, собирает фото и отправляет карточку заявки в группу диспетчера. Python 3.11+, aiogram 3, OpenAI (structured outputs), Supabase (Postgres + Storage).

## Как запустить

1. **Supabase.** Создать проект, открыть SQL Editor и выполнить [supabase/schema.sql](supabase/schema.sql). Скрипт создаёт таблицы `drivers`, `requests`, `request_photos` и публичный бакет `breakdown-photos`. Ключ взять в Project Settings, API: `service_role` (или новый `sb_secret_...`).
2. **Бот.** В @BotFather выполнить `/newbot` и взять токен.
3. **Группа диспетчера.** Создать группу, добавить в неё бота, отправить в группе `/chatid`: бот ответит ID группы.
4. **Окружение.** `cp .env.example .env` и заполнить значения.
5. **Старт:**
   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt
   python -m bot.main
   ```
Тесты логики: `python -m unittest -v` (сторонние пакеты не нужны).

## Как работает

1. **Регистрация** при первом сообщении: имя, телефон кнопкой «Поделиться контактом» (принимается только собственный контакт), госномер (латиница-двойники переводятся в кириллицу).
2. **Описание поломки** свободным текстом. OpenAI возвращает JSON строго по схеме: категория, срочность, место, груз и признак «это вообще поломка». Модель не додумывает: что не сказано, то `null`.
3. **Уточнения** по одному вопросу и только недостающие. Категория, срочность и груз кнопками, место текстом или геолокацией. Если вместо кнопки водитель ответил текстом, ответ тоже разбирается моделью.
4. **Фото** от 1 до 5, можно альбомом или файлом. Фото загружаются в Supabase Storage, в БД хранится ссылка.
5. **Сводка** с кнопками «Отправить» и «Исправить» (выбор поля, переснять фото, отменить заявку).
6. **Диспетчер** получает фото и карточку с кнопками «Принял» и «Помощь выехала». Статус меняется в БД и на карточке, водителю приходит уведомление.

Текущий шаг диалога вычисляется из самой заявки в БД, поэтому перезапуск бота не теряет незаконченные заявки.

**Защита от повторов:**
- одно и то же сообщение Telegram (повторная доставка): `unique (source_chat_id, source_message_id)`, сообщение записывается в БД до вызова OpenAI;
- тот же текст повторно в течение 30 минут: сравнение нормализованного хэша, бот отвечает номером уже созданной заявки;
- одно фото дважды: `unique (request_id, tg_file_unique_id)`;
- двойное нажатие «Отправить» или одновременные нажатия двух диспетчеров: смена статуса условным UPDATE (`where status in (...)`), плюс апдейты одного пользователя обрабатываются по очереди;
- у водителя не больше одного черновика (частичный unique-индекс).

## Что проверено

- Юнит-тесты логики (13 шт.): порядок вопросов, лимиты фото, нормализация ответа модели, хэш для повторов, госномер, длина карточки и экранирование HTML.
- Разбор текста на реальном API (gpt-4o-mini), например «Пробил колесо на М3, 240 км, фура гружёная» даёт колесо, М3 240 км, гружёный, а срочность бот спрашивает; «не заводится, стою» даёт двигатель и «стою на трассе»; «привет» заявку не создаёт.
- Сквозной прогон в Telegram и Supabase (4 заявки, 45 апдейтов, ошибок в логе нет): регистрация с контактом, разбор текста, уточнения по одному вопросу (на «Пробил колесо» бот спросил только срочность, место и груз), ответ текстом вместо кнопки (на вопрос о грузе «Только загрузил» записалось «гружёный»), загрузка фото в Storage (публичные ссылки открываются), сводка и «Исправить», карточка в группе диспетчера, кнопки «Принял» и «Помощь выехала» со сменой статуса и уведомлением водителю, повторная отправка того же текста не создала вторую заявку.

## Что не успели

- Деплой и webhook (сейчас long polling).
- Роли диспетчеров: кнопки может нажать любой участник группы диспетчера.
- При «Фото заново» старые файлы остаются в Storage.
- Голосовые сообщения, тесты хендлеров с моками Telegram и Supabase.
